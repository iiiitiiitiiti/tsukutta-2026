## 019. 日本語のフォントを、ページに出てくる字だけの1ファイルにする

- 日付: 2026-11-12
- 対象: `scripts/page-font.mjs`（新規）・`src/assets/fonts/page-jp.woff2`・`src/assets/fonts/page-jp.json`（新規）・`src/styles/global.css`（`--body`）・`src/pages/index.astro`・`src/components/demos/`（Kaimono・Scoreboard・Flashcards）・`package.json`・`.gitignore`・`README.md`

### 決定

- 日本語の字を `PageJP` という名前の1ファイル（`page-jp.woff2`・804字・185KB）で出す。Noto Sans JP の可変フォントから、ビルド結果の HTML・JS・CSS に出てくる字だけを抜き出して作る。太さ（100〜900）は1ファイルで全部出せる
- 作ったフォントと、入っている字の一覧（`page-jp.json`）をコミットする。作り直すのは `npm run font`
- `npm run build` の最後に、ビルド結果の字が一覧に全部あるかを確かめる。足りなければ止まる。フォントと一覧が別のときに作られたものでも止まる（一覧にフォントの SHA-256 を書いて照らす）。CI でも同じ検査が走るので、字の足りないフォントは公開されない
- 字の指定は `'PageJP', 'Noto Sans JP Variable', 'Noto Sans JP', sans-serif` の順。入力欄に打たれた字など PageJP に無い字だけ、これまでの小分けのファイル（`@fontsource-variable/noto-sans-jp`）が届く
- 小分けのファイルの定義（CSS）は、PageJP が届いてから（または届かないと分かってから）効かせる。そのために PageJP の `@font-face` は head の `<style>` に直接書き、小分けの定義の `<link>` より前に置く。本体の CSS は Astro が head の最後に差し込むので、そこに書くと `onload` が PageJP を知る前に走ってすぐ効いてしまう（Opus のレビューの指摘）
- 残す機能は横書きで効くものだけ（`ccmp`・`locl`・`mark`・`kern`・`palt`・`halt`）。これまでの小分けのファイルに入っている機能から、縦書き用を除いたもの
- かな・英数字・和文の約物は、ページに出てこなくても入れる。入力欄に打たれやすいため
- 元のフォントは google/fonts のコミットを固定した URL から取り、SHA-256 で照らす。置き場は `.cache/fonts/`（コミットしない）
- デモ3つ（買い物・得点板・暗記カード）は字の指定を直接書いているので、そこにも `PageJP` を足した
- 数字用の指定（`--num`）も `'Oswald', 'Arial Narrow', 'PageJP', 'Noto Sans JP Variable', 'Noto Sans JP', sans-serif` にした（同じ日にあとから足した）。日付や月の見出しの「月」「日」は Oswald に無い字で、後ろに日本語のフォントを書いていなかったので端末の文字で出ていた。Noto Sans JP が入っていない機械では本文と違う書体になる。ユーザーが「直す」と決めた
- ページのどこにも端末の文字を使わない（同じ日にユーザーが「デバイスフォントではなく Web フォントを読み込んで使用して」と指示）。残っていた3か所を直した
  - 買い物のデモ: 品名の行・「消す」・お知らせのボタンはスクリプトがあとから作る。`font: inherit` の指定がそこへ届いていなかったので `:global` を付けた。本物のアプリと同じく行の高さ（1.6）も受け継ぐようになり、品名の行は64px から68.6px になった
  - 得点板のデモ: 画面に出る「✕」（U+2715）を「×」（U+00D7）に替えた。U+2715 は Noto Sans JP に無い字で、本物の得点板でも端末の文字で出ている。読み上げ用の文（`aria-label` と知らせの文）は「✕」のまま
  - 暗記カードのデモ: 字の指定の先頭にあった `-apple-system`・`BlinkMacSystemFont`・`Hiragino Sans` を外した。本物は端末の文字で出すアプリなので合わせてあったが、iPhone と Mac ではこのデモだけ別の書体になっていた
- 「×」が増えたのでフォントを作り直した（805字・185KB）

### 背景

決定018で残した件。これまでは字ごとに小分けにされたファイルが約42個・約950KB 届き、届くたびに文字が組み直されていた。ユーザーが「作る」と決めた（2026-11-12）。

### 比較した代替案

| 案 | 却下理由 |
|---|---|
| フォントをコミットせず、CI と手元のビルドのたびに元のフォント（9.6MB）を取って作る | 公開のたびに外からの取得に頼ることになる。開発用のサーバーではフォントが無い |
| 元のフォント（9.6MB）をリポに入れて、ビルドのたびに作る | リポが 9.6MB 大きくなる。字が変わらないビルドでも毎回作ることになる |
| 字が足りないときは警告だけ出して公開する | 警告は CI では誰も読まない。足りない字は小分けのファイルで出るので表示は崩れないが、気づかないまま遅くなる |
| 小分けのファイルの定義をやめ、無い字は端末の文字で出す | 入力欄に打った字だけ別の書体になる |
| 小分けのファイルの定義を、入力欄に触れたときに初めて読む | 仕組みが1つ増える。定義は画面を止めずに読んでいて、入れたままで表示の速さは94〜97点が出ている |
| 太さを1つに固定する（158KB） | ページは400・500・600・700・900の5つを使う。5つ別々に作ると合計が大きくなる |
| 機能を全部残す（298KB） | 縦書き用や旧字体への置き換え先の字形まで連れてくる。このページは横書きだけ |
| フォントを `public/fonts/` に固定の名前で置く | 名前が変わらないと、フォントを作り直した直後に古いものが最大10分使われる。`src/assets/` に置けばビルドが名前に中身の印を付ける |

### 「✕」の出し方で比べた案

| 案 | 却下理由 |
|---|---|
| 記号の入った別の Web フォントを足して「✕」のまま出す | 元のフォントを外から取る必要がある。太さが1つしか無く、太字の所はブラウザが作った太字になる |
| 線で描いた絵（SVG）にする | 「ルール: 5○2✕」のように文の中にも出る。隣の「○」は字のままなので、太さと大きさがそろわない |
| 「╳」（U+2573）にする | 線が細いままで、太字にしても太くならない |
| 「Ｘ」（U+FF38）にする | 英字の X に見える |

### 確かめたこと

- 届くフォント: 45ファイル・1,083KB（Oswald の2つを含む。全文とデモを全部開いた状態）→ 3ファイル・211KB。小分けのファイルは0個
- 文字を持つ要素894個の位置と大きさが、幅1280px・375px とも直す前と同じ（0.1px 単位で一致）。描画に使われた書体ごとの字数も同じ。幅1280px では、エンドロールの57個が横に1px ずれる回が3回に1回あった。幅と高さは同じで、測る瞬間のぶれと見ている
- 遅い回線（400kbps・遅延300ms）でも小分けのファイルは届かない。小分けの定義は3.0秒で届くが、PageJP が届く6.2秒まで効かない（`media` が `print` のまま）ことを確かめた
- 定義をすぐ効かせた場合も、Chrome では小分けのファイルは届かなかった（フォントが届く3秒前に定義が効いた状態で確かめた）。ほかのブラウザは確かめていないので、届いてから効かせる書き方を保険として残した
- `page-jp.woff2` を止めると、これまでどおり小分けのファイルが届き、文字の位置は直す前と同じ
- 買い物の入力欄にフォントに無い字（鰻・鯛）を打つと、小分けのファイルが2つだけ届く
- ビルド結果に無い字を足すと `npm run build` の検査が止まる。一覧の SHA-256 を書き換えても止まる
- `npm run check` 0件、`npm run check:contrast` は幅1280・375・320px とも基準割れ0件
- Lighthouse（スマホ想定・6回）: 表示の速さ 89→94〜97、最初に文字が出るまで 2.9秒→1.4〜1.5秒、届く量 1,009KB→285KB、リクエスト 49→10。ベストプラクティスと SEO は100のまま。アクセシビリティは5回が100、1回が95（表紙のアイコンが積み上がる途中を測り、「かいもの」の丸が隣と重なって見えた回。積み終わった姿では `npm run check:contrast` の小さい押す所が0件）

- `--num` を直したあと: 端末の Noto Sans JP（SemiBold・Medium）で出ていた240字が PageJP で出る。届くフォントは3ファイル・211KB のまま。文字を持つ要素894個の位置と大きさは、幅1280px・375px とも直す前と同じ。`npm run check:contrast` は3つの幅とも基準割れ0件

- 端末の文字を無くしたあと: 全文とデモを全部開いた状態で、描画に使われた書体は PageJP と Oswald だけ（幅1280px・375px。直す前は Segoe UI Symbol 14字・端末の Noto Sans JP 70字・Arial 10字が残っていた）。位置や大きさが変わったのは894個のうち30個で、得点板の「×」まわり（幅16.3px→20px）と買い物の品名の行（高さ64px→68.6px）だけ。`npm run check:contrast` は3つの幅とも基準割れ0件

### 残っていること

- iPhone の Safari と Firefox では確かめていない
- Web フォントが届くまでの一瞬は、端末の文字で出る（`font-display: swap`）。PageJP・Oswald・入力欄に打たれた字のための小分けのファイルのどれも同じ。届くまで文字を隠す指定（`block`）にすれば端末の文字は出なくなるが、遅い回線では最大3秒ほど文字が見えなくなるので変えていない
