## 018. 全体の見直し（表示の速さ・スクショの拡大・共有カード）

- 日付: 2026-11-12
- 対象: `src/pages/index.astro`・`src/components/Shot.astro`・`src/components/ShotZoom.astro`（新規）・`src/components/HeroShelf.astro`・`src/components/demos/Flashcards.astro`・`src/lib/icon.ts`（新規）・`src/styles/global.css`・`public/favicon.svg`・`public/og.png`・`README.md`

### 決定

- 日本語の文字の定義（`@font-face` が約120個、99KB）を本体の CSS から分け、画面を出したあとに読む。画面を止める CSS は 158KB から 61KB（送る量は 45KB から 12KB）になった。届くまでは端末の文字で出る。スクリプトが動かないときは `<noscript>` の中の同じ CSS を読む
- 表紙の「2026」に使う Oswald の600を先読みする。大きな数字が端末の文字から差し替わる時間を縮める
- スクショの `<img>` に縦横の寸法（`width`・`height`）を書く。寸法はビルドのときに画像から読む。書いていなかったので、「くわしく読む」を開く動きが終わったあとに画像が届き、下の中身が画像の高さだけ（Aʻo Hawaiʻi で310px）押し下げられていた
- スクショを押すと画面いっぱいに大きく出す（`ShotZoom.astro`）。年表の中では幅が PC で約500px・スマホで約270px しかなく、撮った画面の中の文字が読めなかった。PC は画面に収まる最大の大きさ、幅900px 未満は幅720px で出して横に動かして見る。閉じ方は「閉じる」ボタン・Esc・画像やその外を押す、の3つ。スクショの右下に大きく見られる印（丸に矢印）を置いた
- スクショは `<a href="画像">` で包む。スクリプトが動かないときや `<dialog>` が無いブラウザでは、リンクとして画像が開く
- 共有したときのカード用に `og:image`・`og:url`・`twitter:card`・`canonical` を足した。画像 `public/og.png`（1200×630）は表紙の年・題・棒グラフ
- タブに出る絵 `public/favicon.svg` を足した。墨色の角丸に、月の色の丸を1・2・3個積んだ棒グラフ。無かったあいだは `favicon.ico` が 404 になり、コンソールにエラーが出ていた
- `<main>` を年表だけから、自己紹介・年表・おわりにを囲む範囲に広げた。年表の囲みは `<div class="tl">` として残した（`.tl-month:last-of-type` が、同じ親の中で最後の `section` を見るため）
- 表紙の序文を、幅900px 未満でも左ぞろえにした。中央ぞろえでは段落の最後の行だけが真ん中に浮いていた。年・題・アドベントカレンダーの一言は中央のまま
- 暗記カードの高さ合わせを、文字のファイルが後から届いたときにも測り直すようにした（これまでは最初の1回だけ）
- 暗記カードの高さ合わせで `checkVisibility()` が無いブラウザ（Safari 17.3 以前）でもエラーが出ないよう直した
- lucide のアイコンを読む処理が3か所に同じ形で書かれていたので `src/lib/icon.ts` にまとめた

### 背景

ユーザーが「修正できるところ、改善できるところを修正して。コーディング、デザイン、内容、全てにおいて検討して」と頼んだ（2026-11-12）。コードと画面（幅375・768・1280・1920px）と原稿を読み直し、Lighthouse（スマホ想定）で測った。

### 比較した代替案

| 案 | 却下理由 |
|---|---|
| ページに出てくる文字だけの小さなフォントを作り、今の約42ファイル・約950KB を1ファイルにする | 元になる全部入りのフォントが手元の npm パッケージに無く、外から取ってくる必要がある。変換の道具も足すことになる。ユーザーに確かめてから別の作業として行う |
| 画面の外の月の帯に `content-visibility: auto` を付けて最初の組み立てを軽くする | 帯の高さが後から決まるので、表紙のアイコンから項目へ飛ぶ位置・上の月の帯・エンドロールの止まる所がずれるおそれがある |
| 拡大表示のあいだ `html` を `overflow: hidden` にして後ろを止める | Windows ではスクロールバーが消えて後ろのページが横にずれる。止めなくても、窓の上でホイールを回して後ろが動かないことを確かめた |
| スクショを別タブで開くリンクだけにする | スマホではページを離れることになり、戻る操作が要る |
| スクショごとに、画面の中身を説明する代替テキストを書く | 11枚ぶんの文を新しく書くことになる。今回は「（名前）の画面を大きく見る」というリンクの名前にとどめた |
| 表紙の序文を中央ぞろえのまま残す | 中央ぞろえは決定002で自分が選んだもので、ユーザーの指定ではない。何行も続く文は左ぞろえのほうが読みやすい |

### 共有カードの画像の作り方

1. ビルドしたページを幅1500px・高さ788px の画面で開き、表紙のアイコンが積み上がるまで待つ（3.5秒）
2. 次の CSS を足して、年・題・棒グラフだけにする

```css
html{scrollbar-width:none}
.page > :not(.hero){display:none!important}
.hero__advent,.hero__body,.cover-shot{display:none!important}
.hero{padding:0!important;height:100vh;display:grid;align-content:center}
.hero__head{grid-row:1/-1;align-self:center}
.hero__title{font-size:44px!important;margin:36px 0 0!important}
```

3. 画面を撮り、1200×630px に縮めて `public/og.png` に置く

棒グラフが変わったら（12月の節を足したときなど）撮り直す。

### 残っていること

- 表示の速さの残りは、文字のファイルが約42個・約950KB あること。届くたびに文字を組み直すので、最初の数秒が重い（上の表の1行目）
- 本物のスマホでは確かめていない。拡大表示は iOS Safari で次の2つがありうる。iOS 15 以前では後ろのページが動く。閉じたあとのフォーカスがスクショに戻らない。どちらも使えなくなるほどではない（Opus のレビューの指摘）
