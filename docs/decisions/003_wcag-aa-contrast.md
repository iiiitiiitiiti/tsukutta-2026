## 003. 文字はすべて WCAG 2.2 の AA に合わせ、帯の上の文字を全部の月で白にそろえる

> 帯の色と白文字は 004 でライトトーン＋黒文字に変えた。AA に合わせる決まりはこのまま残る。

- 日付: 2026-11-05
- 対象: `src/styles/global.css`・`src/pages/index.astro`・`src/components/TimelineItem.astro`・`Counter.astro`・`MonthBar.astro`・`demos/Scoreboard.astro`・`demos/Flashcards.astro`

### 決定

ページをアクセシビリティ AA に合わせる。文字と背景の差はどれも4.5:1以上（24px 以上か 18.66px 以上の太字は3:1以上）にする。

- 4月の帯を #ee6a3c（明るい橙＋墨の文字）から #bf4518（濃い橙＋白の文字）に変える。白との差は5.15
- 7月の帯を #7fb5a2 から #3d7a65（濃い緑。白との差5.04）、8月の帯を #f2be45 から #946600（黄土。5.05）に変え、文字を白にする。どちらも元は白地に置く文字用の色（`--ci`）だった。これで帯の上の文字は全部の月で白になる
- 帯の上の一言・月の件数・数字の添え書きにかけていた opacity 0.8 をやめる。上の色帯の件数の opacity 0.7 もやめる
- 上の色帯で作ったものが無い月の文字を #9aa1ad から #6b7280（白との差4.83）にする
- 得点板の失格の行は opacity 0.55 をやめ、文字を `--ink-soft` にする。○×の数は読み上げ用の文（正解N回、誤答N回）でも出す
- 暗記カードは見えている面だけを読み上げる。裏の答えに aria-hidden を付け、めくるたびに入れ替える

### 背景

ユーザーから「テキストが見づらいところがある。4月とか特に」と言われた。計算すると、4月の一言は墨の文字に opacity 0.8 をかけていたため、差は4.20で AA に届いていなかった。opacity を外しても、明るい中間の橙の上では白の文字も墨の文字もくっきりしない。上の色帯の件数（3.11）と空の月の名前（2.60）も届いていなかった。

### 比較した代替案

| 案 | 却下理由 |
|---|---|
| 4月は今の橙のまま、opacity だけ外す（差5.69） | 数値は通るが、明るい中間の橙に墨の文字はユーザーが見づらいと言った当の組み合わせ |
| 7月・8月は明るい色のまま墨の文字を残す | 7月（6.85）・8月（9.34）は墨で読めるので最初はこの案を採った。4月を直したあと、ユーザーから「文字色を統一したい」と言われて取りやめた |

### 影響範囲

- 002 の「明るい4・7・8月は墨」は取りやめ。全部の月で `--on-c` は既定の白を使う
- 8月の黄土と4月の濃い橙は、どちらも暖色の濃い色になる。並べて撮って見分けられることを確かめた
- 帯の上の縦線（opacity 0.5）と点線（0.6）は飾りなので、文字の基準の外に置いた

### 検証

- Lighthouse のアクセシビリティ: PC・スマホとも100点
- 全文をすべて開いた状態で（この検査は後に `npm run check:contrast` としてリポに入れた）、文字705か所の差を幅1280・375・320pxで計算し、基準を割るもの0件（直す前の版では10件が出ることも確かめた）
- 幅320pxで横のはみ出し無し。押す所はかいもののチェック（20px）以外は24px 以上で、チェックは44px の高さの行全体で押せる
- `npm run check` 0件、`npm run build` 成功。幅1280pxと375px（全文を開いた4月）を撮って目で確かめた
