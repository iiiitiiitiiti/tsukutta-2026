## 001. 洗練された見た目は「日付の強弱」と「色を絞る」で出す

- 日付: 2026-11-05
- 対象: `src/components/TimelineItem.astro`・`MonthBar.astro`・`Counter.astro`・`Shot.astro`・`src/styles/global.css`・`src/pages/index.astro`

### 決定

日付は月の最初の項目だけ「9.05」と大きく出し、同じ月の2件目からは日だけを半分ほどの大きさにする。月の色は線・日付・月の札・線の上の丸・アイコンだけに使い、地は白、回る数字と「くわしく読む」は本文の色にする。表紙の飾りの色帯は消し、月ごとの件数は上の月の色帯のラベルに出す。

### 背景

構成（縦の線・左右交互・月の色・一言＋くわしく読む）は決まっていて、ユーザーから「洗練された LP に仕上げたい」と頼まれた。調べた原文（`~/research/refined-landing-pages/` の report.html）では、AI っぽさは「選んでいない既定値」とそろった反復から来ること、スクロールの演出は中身を補う程度に留めることが挙がった。今の画面は18項目が同じ大きさの日付・同じ色塗りの丸・同じ枠線ボタンで並び、拍子が単調だった。

### 比較した代替案

| 案 | 却下理由 |
|---|---|
| 色を絞り、ボタンを静かにするだけ（日付は全部同じ大きさ） | 一番大きく18回くり返される日付が残り、同じ型のまま整うだけになる（別モデルの壁打ちの指摘） |
| 表紙に月ごとの件数に比例した横棒を置き、開いたときに伸ばす | すぐ上の月の色帯（等幅）と同じ月を2通りの幅で見せることになる。件数は月の色帯のラベルで足りる |
| 数字のある項目を大きく、ない項目を小さくする | 重要度の差が本文に根拠がなく、恣意的に見える |
| スクロールで各項目をふわっと出す | 原文で「中身を補う程度に」と批判の多い演出。自動の動きは回る数字だけで足りる |

### 影響範囲

- `.item + .item` の重なり（左右交互の互い違い）は、日付が小さくなった分 -150px から -120px に戻した。項目の高さを大きく変えたら見直す
- スクショが入っても丸い小窓の細い輪は上に重なる（`Shot.astro` の `::after`）

### 検証

PC 1280px と幅500px で撮り、項目どうしの重なり・はみ出しが無いことを目で確かめた。`npm run check` 0件、`npm run build` 成功。
