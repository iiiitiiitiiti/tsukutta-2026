# 今年つくったもの年表ページ 実装プラン

結論: Astro で1ページの静的サイトを作り、GitHub Pages（リポ `iiiitiiitiiti/tsukutta-2026`）で公開する。本文は note-articles の原稿（`essay/今年つくったもの.md`）を取り込みスクリプトで JSON にして使い、原稿を直したら取り込み直すだけで反映できる形にする。見た目は手帳・紙もの風、仕掛けは「スクロールで時が進む」「各ツールの小さな実物」「数字が回って止まる」の3つ。

## 要件

- 何を作るか: 2026-12-22 担当のアドベントカレンダー（テーマ自由）に出す、今年作ったアプリ・ページの年表ページ（原稿の見出しは18件、ツールは18件。10月19日の3件は2026-11-06 に別々の見出しへ分けた）
- 誰が見るか: 企画の読者全般（作り手の知り合いとは限らない。スマホで読む人が多い前提）
- 成功条件
  - 原稿の全項目が年表順に載り、月見出し・日付・名前・本文・画像枠がそろう
  - 3つの仕掛けがスマホ（iPhone Safari 幅375px）と PC の両方で動く
  - 原稿を直したら `npm run import` 1回でページへ反映できる。原稿とページ側の情報の対応が外れたら取り込みが止まって知らせる
  - 各ツールの URL は載せない（本人指定 2026-11-04）
  - アクセシビリティは WCAG 2.2 の AA（文字の差4.5:1以上など。2026-11-05 ユーザー指定）。Lighthouse のアクセシビリティ90以上、画像は AVIF/WebP で1枚200KB以下
- 前提: 動きは既定でフル再生し、prefers-reduced-motion のガードは入れない（preferences.md 2026-08-10・08-19・11-05）

## 方式の比較

| 案 | 却下理由 |
|---|---|
| Astro（採用） | ― うごき帳・ポートフォリオと同じ構成で、デプロイの workflow をそのまま流用できる。静的出力なので Pages に置くだけで済む |
| 素の HTML/CSS/JS（ビルドなし） | 本文を HTML に手で写すことになり、原稿を直すたびに二重に直す必要が出る |
| note 記事のまま | 2026-11-05 にユーザーが Web ページを選んだ |

## 構成

- `scripts/import-text.mjs`: 原稿の Markdown を読み、`## 4月` のような月の節と、月でない節（冒頭・自己紹介がわりに・おわりに）を分けて `src/data/timeline.json` に書く。`### 4月11日　名前` は項目、その下の段落は本文。`【画像】` 行は撮影の指示なので文は捨て、「画像枠あり」の印だけ残す。原稿のパスは引数で渡す（既定は `../note-articles/essay/今年つくったもの.md`）。JSON はコミットする（CI は note-articles を読めないため）
- `src/data/extras.json`: 原稿に無いページ用の情報を、ツールごとの id（例: `hitotsume`）で持つ。各 id には、どの見出しに属するかを見つけるための名前（`match`）と、回す数字・小さな実物の種類・スクショのファイル名を書く。1つの見出しに複数の id がぶら下がってもよい（今は1見出し1件）
- 取り込みの検査（止めるもの）: extras の `match` に当たる見出しが無い／見出しに当たる extras が無い／月の節の外に `###` がある。（警告だけのもの）回す数字が本文に同じ形で出てこない。原稿が削られて項目が消えたら、extras からその id を消して取り込み直す
- 本文はすべて取り込んだ JSON から出す。index.astro に本文を手で書かない
- `src/pages/index.astro`: 冒頭・自己紹介・月ごとの年表・おわりに
- `src/components/`: 年表の項目、月の区切り、回る数字、小さな実物（ツールごとに1つ）
- `public/shots/`: スクショ（AVIF と WebP）

## 仕掛け

1. スクロールで時が進む: 画面の端に「2026年○月」の表示を固定し、読んでいる月に合わせて数字がめくれる。月ごとに紙の色味を少しずつ変える（4月の淡い緑から11月の枯葉色へ）。月の区切りに入ったかは IntersectionObserver で見る
2. 数字が回って止まる: 473施設・29,961枚・360人・15,639語・369種・21作（disney-archive は2026-11-06 に手を入れた回数から人物名鑑の人数へ替えた。同日に全部を数え直した）。値は extras を正とし、本文の数字と食い違えば取り込みで警告する。最初に見えたときだけ桁ごとに回って左から止まり、画面の外へ出て戻っても回り直さない（うごき帳「数字が回って止まる実績表示」と同じ作り。回り直さないのは 2026-11-06 ユーザー指示）
3. 各ツールの小さな実物（まず3件、時間があれば5件足す。ほかはスクショだけ）。2026-11-06 に「本物と違いすぎて参考にならない」と言われ、本物のコードから見た目と動きを写した小型版に作り直した（docs/decisions/005）
   - 先にやる3件
     - クイズ得点板: m○n× の解答者カード3枚。ロック・得点順の並べ替え・トロフィーで WINNER 画面
     - 暗記カード: 本物の学習画面。めくる・2択の評価・左右のスワイプ・結果のゲージ。問題はユーザーが選んだ5問（2026-11-06 指定。ほかの人のクイズは載せない）
     - かいもの: 本物の画面。チェックで購入済みへ・下の欄で足す（お店を当てる）・左になぞって消す
     - 時間があれば足す5件
   - がまんログ: 金額を選ぶと「ラーメン何杯ぶん」に換わる
   - 作問レビュー: ことのはガチャを1回引ける（語は10語ほどの見本）
   - ひとつめ: 「一手済んだ」で次の一手に替わる
   - うごき帳: 下線が伸びるリンクと浮き上がるカード
   - いきもの手帳: ページが束で積み上がる

## 見た目

2026-11-05 に作り直した。最初の手帳・紙もの風は、ユーザーが見て「AI臭がすごい」と判断し、参考画像（縦の線に年を置いて左右交互に並べる年表・月ごとに色を変えた横の帯など5枚）の方向に変えた。

- 形: 中央の縦線に日付を置き、項目を左右交互に互い違いで並べる。スマホでは線を左端に寄せる
- 幅: PC の表示幅は1200px（上の色帯・表紙・序文・年表の枠。2026-11-05 ユーザー指定）。自己紹介とおわりには960px（2026-11-06 ユーザー指定）。表紙の棚の画像は640px のまま
- 上に月の色帯を固定し、読んでいる月の帯を太くする（月のツメの代わり）。帯はエンドロールの手前で止まる。月ごとの数は出さない（2026-11-06、docs/decisions/008）
- 色: 月ごとに6色のライトトーン（4月 橙・7月 若緑・8月 山吹・9月 青緑・10月 藤青・11月 桃。11月は 2026-11-06 に灰から替えた、docs/decisions/010）。月の節はその色で横いっぱいに塗った帯にし、文字・線・線の上の丸は全部の月で黒に置く（2026-11-05 AA に合わせて変更、docs/decisions/003・004）。アイコンは白い丸の中にその月の色で描く。「くわしく読む」で開く全文は白い面にのせる
- 帯の地は、月の見出しの所はその月の色のまま、下へ行くほど次の月の色へ移るグラデーションにする。帯の境目で色がつながり、季節が移るように見える。色は oklch で混ぜて中ほどの濁りを避け、最後の11月から白へだけ oklab で混ぜる（2026-11-06、docs/decisions/009・010）。帯の地は月の色を明るく薄くした色にする（docs/decisions/011）。ページ内のリンクは滑らかにスクロールする。年表の終わりは点線を下へ伸ばし、輪郭だけの次の月の数字と「12月へつづく」を置く。原稿に12月の節を足せば表紙・上の色帯・年表に12月が出る（011）
- 月の見出しは帯の頭に大きな数字で置き、その月に作った数を添える
- 表紙: 作った18件のアイコンが落ちてきて月の列に積み上がり、月ごとの作った数の棒グラフになる。アイコンと月の数字は年表へのリンク。指したアイコンの日付と名前は、吹き出しではなくグラフ左上の空いた所に出す。落ちるアイコンは題と序文の後ろを通す。PC では左に年・題・序文、右にグラフ（2026-11-06、docs/decisions/005・006）
- 締め: おわりにの後に、黒い画面いっぱいのエンドロール。題の札を真ん中に出してから、作った物を日付順に一定の速さで流し、クレジット（企画・注文・制作・書体・アイコン）へ続く。「2026 18こ作った」の札だけが真ん中で止まり、上の行はそのまま抜けていく。止める・もう一度流すボタン付き。近くまでスクロールすると画面にぴったり収まる所で止まる（2026-11-06、docs/decisions/006・008）
- ページの一番下に「上に戻る」ボタン
- 表紙（スマホ）・自己紹介・おわりには白地で、年表と同じく中央にそろえる
- 日付: 月の最初の項目だけ「9.05」と大きく出し、同じ月の2件目からは日だけを半分ほどの大きさで出す。月は札と線の色で分かるので、同じ「9.」を何度も並べない。全項目が同じ大きさの日付だと拍子が単調になる（2026-11-05、洗練された LP の調べもの ~/research/refined-landing-pages/ と別モデルの壁打ちから）
- 文字: 日付と数字は細身の欧文書体 Oswald、本文は Noto Sans JP（自作のアプリ・サイトの書体の決まり）
- 本文: 線の上には日付・名前・一言・アイコン（スクショが入ってもアイコンのまま。docs/decisions/010）だけを置き、「くわしく読む」で全文・実物・大きなスクショが開く。一言はつくったもの棚の説明をもとにした。項目と月の見出しはスクロールで画面に入ると下から現れ、全文は高さが伸びて中身が順に浮かんで開く（2026-11-06、docs/decisions/006）。原稿の「- 語：説明」が続く所は定義リストで出す

## 画像

- スクショは本人が使っている実物を撮る。個人の記録が写るもの（がまんログ・かいもの・動物園・水族館ログ）は見本のデータを入れた手元の開発サーバーで撮る
- 自分だけが開けるページ（Artifact・disney-archive）は、ユーザーに撮ってもらうか、手元で開ける状態のものを撮る。disney-archive は公式ブログの記事本文が写らないよう名鑑の側で撮る。Worklog は仕事の記録が写るのでスクショを載せない
- 撮れるまでは画像枠に「画像を準備中」の紙を置く

## 公開

- 最初から GitHub に private で作って push し続ける。無料の契約では private のリポから Pages を出せないので、公開までは build だけを CI で確かめる
- 原稿と画像の個人情報をユーザーが確かめたら、リポを public に切り替えて Pages を有効にする（本文に自己紹介と暮らしの話が入るため、確認前に公開しない）
- 原稿の凍結日を12月15日ごろに置き、それ以降は取り込み直さない（日付はユーザーが決める）
- 公開 URL は https://iiiitiiitiiti.github.io/tsukutta-2026/ になる見込み（未確認）

## 手順と確かめ方

1. Astro の雛形・取り込みスクリプト・JSON → `npm run import` で見出し16件・ツール18件・月6つが JSON に入り、extras の id を1つ消すと取り込みが止まることを確かめる
2. 年表の骨組み（月・項目・本文・画像枠）と紙の見た目 → プレビューを幅375pxと1280pxで撮って目視
3. スクロールで時が進む → 月が切り替わる位置で表示がめくれることを撮って確かめる
4. 回る数字 → 6つの数字が見えたときに回り、最後に正しい値で止まる
5. スクショの撮影と差し替え → 画像の大きさと個人情報の写り込みを確かめる
6. 小さな実物（先に3件、時間があれば5件） → 1件ずつ操作して動きを確かめる。キーボードでも操作できる
7. `npm run check` と `npm run build`、Lighthouse → 通ったらユーザーに確認を頼み、OK が出たら公開
