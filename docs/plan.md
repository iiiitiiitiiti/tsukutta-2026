# 今年つくったもの年表ページ 実装プラン

結論: Astro で1ページの静的サイトを作り、GitHub Pages（リポ `iiiitiiitiiti/tsukutta-2026`）で公開する。本文は note-articles の原稿（`essay/今年つくったもの.md`）を取り込みスクリプトで JSON にして使い、原稿を直したら取り込み直すだけで反映できる形にする。見た目は手帳・紙もの風、仕掛けは「スクロールで時が進む」「各ツールの小さな実物」「数字が回って止まる」の3つ。

## 要件

- 何を作るか: 2026-12-22 担当のアドベントカレンダー（テーマ自由）に出す、今年作ったアプリ・ページの年表ページ（原稿の見出しは16件、ツールは18件。10月19日の見出しに3件入っている）
- 誰が見るか: 企画の読者全般（作り手の知り合いとは限らない。スマホで読む人が多い前提）
- 成功条件
  - 原稿の全項目が年表順に載り、月見出し・日付・名前・本文・画像枠がそろう
  - 3つの仕掛けがスマホ（iPhone Safari 幅375px）と PC の両方で動く
  - 原稿を直したら `npm run import` 1回でページへ反映できる。原稿とページ側の情報の対応が外れたら取り込みが止まって知らせる
  - 各ツールの URL は載せない（本人指定 2026-11-04）
  - Lighthouse のアクセシビリティ90以上、画像は AVIF/WebP で1枚200KB以下
- 前提: 動きは既定でフル再生し、prefers-reduced-motion のガードは入れない（preferences.md 2026-08-10・08-19・11-05）

## 方式の比較

| 案 | 却下理由 |
|---|---|
| Astro（採用） | ― うごき帳・ポートフォリオと同じ構成で、デプロイの workflow をそのまま流用できる。静的出力なので Pages に置くだけで済む |
| 素の HTML/CSS/JS（ビルドなし） | 本文を HTML に手で写すことになり、原稿を直すたびに二重に直す必要が出る |
| note 記事のまま | 2026-11-05 にユーザーが Web ページを選んだ |

## 構成

- `scripts/import-text.mjs`: 原稿の Markdown を読み、`## 4月` のような月の節と、月でない節（冒頭・自己紹介がわりに・おわりに）を分けて `src/data/timeline.json` に書く。`### 4月11日　名前` は項目、その下の段落は本文。`【画像】` 行は撮影の指示なので文は捨て、「画像枠あり」の印だけ残す。原稿のパスは引数で渡す（既定は `../note-articles/essay/今年つくったもの.md`）。JSON はコミットする（CI は note-articles を読めないため）
- `src/data/extras.json`: 原稿に無いページ用の情報を、ツールごとの id（例: `hitotsume`）で持つ。各 id には、どの見出しに属するかを見つけるための名前（`match`）と、回す数字・小さな実物の種類・スクショのファイル名を書く。1つの見出しに複数の id がぶら下がってよい（10月19日の3件）
- 取り込みの検査（止めるもの）: extras の `match` に当たる見出しが無い／見出しに当たる extras が無い／月の節の外に `###` がある。（警告だけのもの）回す数字が本文に同じ形で出てこない。原稿が削られて項目が消えたら、extras からその id を消して取り込み直す
- 本文はすべて取り込んだ JSON から出す。index.astro に本文を手で書かない
- `src/pages/index.astro`: 冒頭・自己紹介・月ごとの年表・おわりに
- `src/components/`: 年表の項目、月の区切り、回る数字、小さな実物（ツールごとに1つ）
- `public/shots/`: スクショ（AVIF と WebP）

## 仕掛け

1. スクロールで時が進む: 画面の端に「2026年○月」の表示を固定し、読んでいる月に合わせて数字がめくれる。月ごとに紙の色味を少しずつ変える（4月の淡い緑から11月の枯葉色へ）。月の区切りに入ったかは IntersectionObserver で見る
2. 数字が回って止まる: 473施設・29,961枚・1,321回・5,560語・168種・21作。値は extras を正とし、本文の数字と食い違えば取り込みで警告する。見えたら桁ごとに回って左から止まる（うごき帳「数字が回って止まる実績表示」と同じ作り）
3. 各ツールの小さな実物（まず3件、時間があれば5件足す。ほかはスクショだけ）
   - 先にやる3件
     - クイズ得点板: 正解・誤答ボタンで点が動き、勝ち抜けで紙吹雪
     - 暗記カード: タップでめくれるカード3枚。問題はこの年表の中身から作った（自作のクイズを載せたくなったらユーザーが選ぶ）
     - 時間があれば足す5件
   - がまんログ: 金額を選ぶと「ラーメン何杯ぶん」に換わる
   - 作問レビュー: ことのはガチャを1回引ける（語は10語ほどの見本）
   - ひとつめ: 「一手済んだ」で次の一手に替わる
   - うごき帳: 下線が伸びるリンクと浮き上がるカード
   - いきもの手帳: 168枚のページが束で積み上がる
   - かいもの: 品物をチェックすると購入済みへ移る

## 見た目

2026-11-05 に作り直した。最初の手帳・紙もの風は、ユーザーが見て「AI臭がすごい」と判断し、参考画像（縦の線に年を置いて左右交互に並べる年表・月ごとに色を変えた横の帯など5枚）の方向に変えた。

- 形: 中央の縦線に日付を置き、項目を左右交互に互い違いで並べる。スマホでは線を左端に寄せる
- 上に月の色帯を固定し、読んでいる月の帯を太くする（月のツメの代わり）
- 色: 月ごとに6色（4月 橙・7月 灰緑・8月 黄・9月 深緑・10月 紺・11月 墨）。日付の数字・線・丸もその月の色
- 文字: 日付と数字は細身の欧文書体 Oswald、本文は Zen Kaku Gothic New
- 本文: 線の上には日付・名前・一言・アイコン（スクショが入ればその丸い切り抜き）だけを置き、「くわしく読む」で全文・実物・大きなスクショが開く。一言はつくったもの棚の説明をもとにした

## 画像

- スクショは本人が使っている実物を撮る。個人の記録が写るもの（がまんログ・かいもの・動物園・水族館ログ）は見本のデータを入れた手元の開発サーバーで撮る
- 自分だけが開けるページ（Artifact・disney-archive）は、ユーザーに撮ってもらうか、手元で開ける状態のものを撮る。disney-archive は公式ブログの記事本文が写らないよう名鑑の側で撮る。Worklog は仕事の記録が写るのでスクショを載せない
- 撮れるまでは画像枠に「画像を準備中」の紙を置く

## 公開

- 最初から GitHub に private で作って push し続ける。無料の契約では private のリポから Pages を出せないので、公開までは build だけを CI で確かめる
- 原稿と画像の個人情報をユーザーが確かめたら、リポを public に切り替えて Pages を有効にする（本文に自己紹介と暮らしの話が入るため、確認前に公開しない）
- 原稿の凍結日を12月15日ごろに置き、それ以降は取り込み直さない（日付はユーザーが決める）
- 公開 URL は https://iiiitiiitiiti.github.io/tsukutta-2026/ になる見込み（未確認）

## 手順と確かめ方

1. Astro の雛形・取り込みスクリプト・JSON → `npm run import` で見出し16件・ツール18件・月6つが JSON に入り、extras の id を1つ消すと取り込みが止まることを確かめる
2. 年表の骨組み（月・項目・本文・画像枠）と紙の見た目 → プレビューを幅375pxと1280pxで撮って目視
3. スクロールで時が進む → 月が切り替わる位置で表示がめくれることを撮って確かめる
4. 回る数字 → 6つの数字が見えたときに回り、最後に正しい値で止まる
5. スクショの撮影と差し替え → 画像の大きさと個人情報の写り込みを確かめる
6. 小さな実物（先に3件、時間があれば5件） → 1件ずつ操作して動きを確かめる。キーボードでも操作できる
7. `npm run check` と `npm run build`、Lighthouse → 通ったらユーザーに確認を頼み、OK が出たら公開

## やらないこと

- 各ツールへのリンク
- 英語版・ダークモード
- note への同時掲載（Web ページだけにすると 2026-11-05 に決定）
- 本文の推敲（原稿は記事レビュー帳でユーザーが削る。ページは取り込むだけ）
